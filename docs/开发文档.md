# 开发文档

对外宣传与玩法见 [README](../README.md)。这份文档给自己用：目录结构、本地开发、地图格式、构建部署、校验命令。

## 数据模型

```
书        药理学                     ← public/maps/<bookDir>/book.json
└─ 章节    胆碱受体阻断药              ← 章节文件，含 fragments
   └─ 知识碎片  总论与药动学          ← 一局（菜单最底层）
      └─ 句元（棋盘上的判定单位）      ← 只在棋盘上出现
```

菜单只到「知识碎片」这一层；句元只在对局棋盘上出现。

## 本地开发

```powershell
npm install --include=dev
npm run dev
```

打开 `http://127.0.0.1:5175/`。手机连同一 Wi-Fi 访问 `http://<电脑IP>:5175/`。

## 地图目录与格式

```
public/maps/
  index.json                  ← 自动生成，不要手改
  pharmacology/
    book.json                 ← 书元信息 + 章节索引
    01-anticholinergic.json   ← 章节（含 fragments）
```

`book.json`：

```json
{
  "schemaVersion": 2,
  "id": "pharmacology",
  "title": "药理学",
  "author": "",
  "contentVersion": 2,
  "contentNote": "v2 词级篡改规则生成",
  "chapters": [
    { "id": "anticholinergic", "title": "胆碱受体阻断药", "order": 1, "file": "01-anticholinergic.json" }
  ]
}
```

章节文件：

```json
{
  "id": "anticholinergic",
  "title": "胆碱受体阻断药",
  "fragments": [
    {
      "id": "anticholinergic-01",
      "title": "总论与药动学",
      "order": 1,
      "recommendedRounds": 12,
      "pages": [{ "id": "p1", "title": "第 1 页", "unitIds": ["anticholinergic-01-s01"] }],
      "units": [
        {
          "id": "anticholinergic-01-s01",
          "paragraph": 1,
          "corruptNow": false,
          "original": "原文句子",
          "wrongDisplay": "篡改版句子",
          "correctOption": "忠实改写",
          "wrongOptions": ["错误项1", "错误项2", "错误项3"]
        }
      ]
    }
  ]
}
```

字段要点：

| 字段 | 说明 |
|---|---|
| `book.json` 的 `chapters[].file` | 必须与实际文件名一字不差，否则整本书被 `index-books.mjs` 跳过 |
| `chapters[].order` | 章节排序，递增整数 |
| `fragments[].order` | 碎片排序，决定菜单顺序 |
| `fragments[].recommendedRounds` | 建议轮数，写进对局设置默认值 |
| `fragments[].pages[].unitIds` | 分页时每一页包含哪些句元 id |
| `units[].id` | 建议 `<fragmentId>-s01` 形式，**全局唯一**，存档按它记账 |
| `units[].paragraph` | 在原章节里的段号，用于「文章回顾」还原上下文 |
| `units[].corruptNow` | 开局是否就是这个句元已被篡改 |
| `wrongOptions` | 3 个错误选项，加上 `correctOption` 共 4 选 1 |

文件夹与文件名用英文；中文标题写在文件内容里。

## 用 skill 做书（推荐）

项目自带地图锻造 skill：`skills/juyuan-map-forge/`。它把「文本 → 地图」整条流水线走完，不用手写 JSON。

### 装到哪

DSH 只从用户级目录加载 skill，**项目里的 `skills/` 不会被自动识别**（调用 `skill juyuan-map-forge` 会报 unknown）。所以要复制一份到：

```
C:\Users\30758\.dsh\skills\juyuan-map-forge\
```

```powershell
Copy-Item skills\juyuan-map-forge\* "$env:USERPROFILE\.dsh\skills\juyuan-map-forge" -Recurse -Force
```

装完新开对话，说「用 juyuan-map-forge 把这一章做成地图」即可触发；也可以在对话里直接用 skill 名调用。

> 两份会漂移：项目 `skills/` 是源，改完记得重新复制一次到用户目录。

### 它会做什么

| 步骤 | 产物 |
|---|---|
| 0 拆书：一章一个 txt | `.work/<bookId>/chapters/01-<chapter>.txt` |
| 1 切句（按 quality 过滤） | `sentences.json` |
| 2 规划知识碎片（18–30 句元/碎片） | `plan.json` |
| 3 每 6–8 句一批生成四选一 | `units-N.json` → `merge-units` → `units.json` |
| 4 内容硬校验 | `validate-content.mjs` 必须 PASS |
| 5 语义判定（恰好 1 个 faithful） | 不合规的换算子重生成 |
| 6 DP 分页（目标页长 12） | `pages.json` |
| 7 组装 | `build-book.mjs` → `public/maps/<bookId>/`，并自动更新 `index.json` |
| 8 最终校验 | `validate-map.mjs` 必须 PASS |

### 手工跑脚本

在项目根目录（脚本路径相对项目，skill 里也是这么写的）：

```powershell
# 切句
node skills/juyuan-map-forge/scripts/split.mjs .work/<bookId>/chapters/01-<chapter>.txt .work/<bookId>/01-<chapter>/sentences.json

# 合并分片
node skills/juyuan-map-forge/scripts/merge-units.mjs .work/<bookId>/01-<chapter>/units.json .work/<bookId>/01-<chapter>/units-1.json .work/<bookId>/01-<chapter>/units-2.json

# 内容校验（必须 PASS）
node skills/juyuan-map-forge/scripts/validate-content.mjs .work/<bookId>/01-<chapter>/units.json .work/<bookId>/01-<chapter>/sentences.json

# 分页
node skills/juyuan-map-forge/scripts/paginate.mjs .work/<bookId>/01-<chapter>/units.json .work/<bookId>/01-<chapter>/pages.json 12

# 组装成 v2 书（会写 public/maps/<bookId>/ 并自动跑 index-books）
node skills/juyuan-map-forge/scripts/build-book.mjs .work/<bookId>/meta.json
```

### 质量红线（不达标就丢，不硬凑）

- 找不到 4 个互异单点算子 → 丢弃该句
- 两个选项都说得通 → 重生成
- 差异依赖原文之外的知识 → 重生成
- 连续两次失败 → 丢弃并记录编号
- v1 迁移内容标 `contentVersion: 1`，不要假装合规

英语背单词书走另一套规则（见 `references/content-types.md`），不要套医学规则。

## 手工做书（不装 skill 时）

```powershell
mkdir public/maps/mybook                                   # 1. 建目录（英文名）
# 2. 写 public/maps/mybook/book.json
#    写 public/maps/mybook/01-mybook.json（章节 + fragments + units）
node scripts/validate-map.mjs public/maps/mybook/book.json  # 3. 校验结构
npm run index:books                                        # 4. 生成清单（必须）
npm run dev                                                # 5. 本地看效果
git add public/maps
git commit -m "新增《书名》"
git push                                                    # 6. 上线
```

**漏了第 4 步，菜单里不会出现新书。** `npm run build` 也能触发索引（`prebuild`），但它顺带打包，慢一点。

## 给已有书补章节

1. 新建章节文件，例如 `public/maps/pharmacology/02-cholinergic.json`，顶层 `id` / `title` 与下面追加的那条一致
2. 在 `book.json` 的 `chapters` 数组追加一条：

```json
{ "id": "cholinergic", "title": "拟胆碱药", "order": 2, "file": "02-cholinergic.json" }
```

3. 校验 + 重建索引 + 构建 + 推送：

```powershell
node scripts/validate-map.mjs public/maps/pharmacology/book.json
npm run index:books
npm run build
git add public/maps
git commit -m "药理学：新增「拟胆碱药」章节"
git push
```

## 只补句元（结构不变）

直接编辑章节 JSON 的 `units` / `pages`，然后：

```powershell
npm run build
git add public/maps
git commit -m "药理学：补充句元"
git push
```

书数、碎片数都没变，`index:books` 可跑可不跑。

## 内容规范

句元不是随便改的句子——**篡改项必须守词级规则**，否则题目会变成"读起来就知道不对"的废题：

- 篡改只能在**原句上做词级替换**，禁止结构改写（不增删分句、不调语序、不改标点、不做因果倒置）
- 与 `original` 的字符 diff **只有 1 段连续差异**，且不跨标点
- **一个选项只改一处**
- 允许的算子：限定/范围、判断/否定、数字、名词/专名、方向、主客（只加"被/受"）、时间、程度/频率、情态、单位、人群、给药途径、部位侧别、比较词
- `correctOption` 是唯一例外：允许同义改写，不必与原文逐字相同

英语背单词类内容另有规则（拼写篡改、释义改写等），与医学/教材文本不混用。完整清单见 `skills/juyuan-map-forge/`。

## 校验

```powershell
node scripts/validate-map.mjs public/maps/pharmacology/book.json
node --experimental-strip-types --no-warnings scripts/check.mjs
```

第一条查地图 JSON 结构；第二条跑规则引擎回归。

## 部署到 GitHub Pages

**线上地址：<https://gushengsheng.github.io/sentences/>**（仓库 `gushengsheng/sentences`，推 `main` 自动发布）

免费账号的 Pages 只支持公开仓库。产物地址规律：

```
https://<用户名>.github.io/<仓库名>/
```

### 一次性准备

```powershell
# 这台机器用 schannel 推 GitHub 会报 SEC_E_NO_CREDENTIALS，必须换 openssl 后端
git config --global http.sslBackend openssl

# 提交身份（每个提交都会带上）
git config --global user.name  "你的用户名"
git config --global user.email "你的邮箱"
git config --global init.defaultBranch main
```

### 建仓库并首次推送

在 <https://github.com/new> 建一个 **Public** 仓库，**不要**勾 README / .gitignore / license（否则第一次 push 会和本地历史打架）：

```powershell
git init
git add .
git commit -m "sentences v2"
git remote add origin git@github.com:<用户名>/<仓库名>.git
git push -u origin main
```

用 SSH 地址（`git@github.com:` 开头）比 HTTPS 省事，不用配 token。

### workflow

`.github/workflows/deploy.yml`：`npm ci` → `npm run build`（注入 `GH_REPO` / `GITHUB_ACTIONS`）→ 上传 `dist` → 发布。

`vite.config.ts` 靠这两个变量把 `base` 设成 `/<仓库名>/`，所以**仓库叫什么名字都不用手改配置**。反过来说：**所有运行时 fetch 都必须经过 `assetUrl()` 拼 `import.meta.env.BASE_URL`**，写死 `/maps/...` 会在子路径下 404。

**Pages 的源必须手动开一次**：仓库 Settings → Pages → Build and deployment → Source 选 **GitHub Actions**。别指望 workflow 自动开——`configure-pages` 的 `enablement: true` 需要 admin 级 token，个人账号下会报 `Resource not accessible by integration`，整个 build 直接挂。开一次之后就不用再管了。

### 日常更新地图

```powershell
npm run index:books          # 改了书/章节结构才需要，新书必须跑
npm run build                # 建议，能提前发现构建问题
git add public/maps
git commit -m "更新《书名》章节"
git push                     # 触发 Actions，约 1 分钟
```

推送完去仓库 **Actions** 页等 `Deploy to GitHub Pages` 变绿，然后刷新页面。手机端记得下拉强制刷新或清缓存——`index.json` 有缓存，最容易误判成"没更新成功"。

### 排错

| 现象 | 原因 |
|---|---|
| `SEC_E_NO_CREDENTIALS` | `http.sslBackend` 没设成 `openssl` |
| Actions 红在 `npm ci` | `package.json` 改了但没提交 `package-lock.json`，本地先跑 `npm install` 再提交 |
| 部署成功但打开白屏 | `base` 不对：确认 workflow 里传了 `GH_REPO` 和 `GITHUB_ACTIONS` |
| 菜单少一书 | 忘了跑 `npm run index:books`，或 `book.json` 里章节 `file` 路径写错 |
| 页面 404 | Pages 源还没切成 GitHub Actions |

## 已知限制

- 地图只能放在 `public/maps/` 重新部署，还没有运行时导入
- 进度存在浏览器 localStorage，换设备不跟随
- 手机端没有点击二次确认
- 没有 PWA 离线缓存
- 没有 APK（规划中）
- `bees` / `sleep` 两本书是 v1 手写内容，部分篡改未按词级规则生成（书里已标 `contentVersion: 1`）
